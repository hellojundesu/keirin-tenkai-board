# 東スポ出走表コメント取得

## 目的

従来のWINTICKETコメント取得に依存せず、東スポ競輪の公開ページにある「選手コメント」を、保存済み出走表のレース・車番・選手名と照合して保存する。

## 動作

- `出走表を毎朝取得` の完了情報を受けて `.github/workflows/cloud-comments.yml` が動く。
- 日付、競輪場、レース番号、車番、選手名が一致したコメントだけを `race_pre` として採用する。
- コメント欄がないレースと、コメント欄に載っていない選手は、取得失敗ではなく `not_published` として明示する。
- ページ未発見、通信失敗、解析不一致は再取得対象にし、保存後の全件検証が成功しない限りジョブを成功にしない。
- レース明細を先に保存し、すべて同じ世代になった後で日付マニフェストを保存する。

既存の `inspection` と `result` は削除しない。再実行が失敗した場合も、保存済みの `race_pre`、`inspection`、`result` 本文を空値で上書きしない。

## 衝突と同時実行

- 同じ競輪場・レース番号を名乗る東スポページが複数見つかった場合は停止する。
- レースID、登録番号、車番の重複は保存前に拒否する。
- ワークフローの同時実行は `keirin-tospo-comments` グループで直列化する。
- 保存は既存の限定CASを使う。競合時は未完了キューを残し、日付マニフェストを先に公開しない。

## 反映手順

1. 検証ブランチのテスト結果と差分を確認する。
2. `cloud-comments.yml` を含む変更を本番ブランチへ反映する。
3. 最初は手動実行で対象日を指定し、取得証跡、保存証跡、全件検証証跡を確認する。
4. `cloud_comment_manifest` の `source_provider` が `tospo-keirin`、`retry_required` が0であることを確認する。
5. その後の出走表定時取得から自動連携を確認する。

DDL、既存行の一括更新、既存レコードの削除は不要。

## ロールバック

1. `cloud-comments.yml` を直前の本番版へ戻し、東スポ自動取得を止める。
2. 必要なら直前のWINTICKET版を手動実行する。CAS保存時に既存本文は保護される。
3. 東スポ世代を削除しない。旧形式の `inspection` / `result` 読取互換性を残しているため、データ削除なしで戻せる。
4. 戻した後、保存済みマニフェストと全依存レースを再検証する。

## 今回の範囲外

このリポジトリで行うのは、東スポコメントの取得、照合、クラウド保存、保存後検証まで。別ディレクトリにあるローカル評価ツールの画面へ `race_pre` を表示する変更は含めない。
