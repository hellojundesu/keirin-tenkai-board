# 競輪場単位公開の検証結果

実施日: 2026-11-19 JST  
対象: `fix/atomic-cloud-generation-publication` 検証ブランチ  
本番変更: なし

## 実装済み

- 保存済みmanifestの `expectedRaces` と `completedVenues` を使い、日全体がpartialでも完全な競輪場だけを抽出する。
- 競輪場世代を不変レコードとしてステージし、同一世代ID・異なる内容を拒否する。
- 場ごとのCAS revisionで公開ポインタを切り替える。
- 場ポインタと日全体インデックスを同一DBトランザクションで更新する。
- 旧世代を削除せず、CAS付きで旧世代へ再公開できる。
- 日インデックスからコメント対象カタログを作り、世代混在を拒否する。
- RLSを有効化し、一般ロールへのテーブル／関数権限を付与しない候補DDLを用意した。

## 合格した検証

- 2026-11-18の実データ79レースを8場へ欠落・重複なく分割。
- 1場を12/12から11/12へ欠損させたpartial日で、残り7場67レースを公開候補にし、欠損場だけを拒否。
- 部分失敗時の旧世代維持。
- 同一内容の再ステージ／再公開の冪等性。
- 同一世代IDに異なる内容を混ぜた場合の拒否。
- 古いrevisionでの切替拒否。
- 同時公開で1処理だけが勝つ参照モデル。
- 8場を順次切り替えた日インデックスが79レースを一意に列挙。
- 新日インデックスから作るコメント対象79件が従来ファイル由来カタログと一致。
- コメント読取で競輪場世代を混在させた場合の拒否。

## 未検証

- Windowsのアプリケーション制御が一時 `postgres.exe` の起動を拒否したため、候補DDLの実PostgreSQL実行と実DB並列トランザクション試験は未完了。自動試験ランナーとSQL試験は用意済み。
- Supabase非本番プロジェクトでのRLS、Data API公開範囲、service role、RPC、実行計画、DB Advisor。
- Edge Function / OIDCゲートウェイの新RPCプロトコル。現行ゲートウェイは従来 `shared_snapshots` CAS用のため未変更。
- GitHub Actionsとの結合、通信切断、HTTP 400/403/429/500、タイムアウト。
- 本番バックアップ取得と別DBへの復元試験。
- GitHub Pages、外部利用者、競輪評価ツールを含む全読取クライアントの実接続比較。
- 結果・払戻し・コメントの本番相当end-to-end。コード上はrace_id依存を維持するが、実サービス結合は未実施。

## 判定

Python参照モデルと2026-11-18実データの場単位分割は合格。候補DDLを本番へ適用できる段階ではない。非本番PostgreSQL／Supabase、ゲートウェイ、Actionsの結合試験とバックアップ復元試験が次の必須ゲート。
